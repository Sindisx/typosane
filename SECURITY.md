# Security

Не публикуйте описание уязвимости, приватный текст, crash dump или proof of
concept в открытом issue.

Используйте GitHub Private Vulnerability Reporting этого репозитория. До
появления выделенного security-адреса это основной приватный канал связи с
владельцем проекта.

Особенно важны сообщения о случаях, когда приложение:

- обрабатывает Secure Input или поле, помеченное системой как парольное;
- сохраняет или отправляет набранный текст;
- заменяет текст после смены поля, процесса, курсора или исходного слова;
- пишет исходный текст в log/crash report;
- после появления механизма обновлений принимает неподписанное или более
  старое обновление;
- распространяется с повреждённой подписью либо checksum.

Для воспроизведения используйте только искусственный текст. Никогда не
присылайте пароль, token, signing key или реальную переписку.

Политика coordinated disclosure и safe-harbor будет юридически проверена и
дополнена до первого публичного релиза.
